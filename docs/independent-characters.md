# 独立した機体・装備

Rules 5 では `霊夢A / 霊夢B / 魔理沙A / 魔理沙B / 早苗A / 早苗B` を順に `0..5` として扱う。接続後、原作のキャラクター・装備画面を1P、2Pの順に使用する。画面には原作ASCII描画で必要な `1P` / `2P` だけを表示し、各自の方向・決定・取消入力を使う。2Pを確定するまでゲームを開始しない。確定後のactor分離はRules 4と共通。デモ・原作リプレイには独立機体を適用しない。

原作 `MainMenu` の状態6/7を再利用する。1Pの装備確定後は原作の取消アニメーションと資源解放を通り、状態6へ戻って2Pを受け付ける。Practiceは装備確定後10フレームで先へ進む固有経路、通常・Extraは40フレームの経路の両方を接続する。装備の取消はそのプレイヤーのキャラクター選択へ戻る。2Pが難易度へ戻った場合は1Pから選び直す。Practice面選択、ステージ・会話の機体は1Pへ復元する。

オンラインは既存の確定P1/P2入力で進め、別の非同期な選択通知は追加しない。選択中のプレイヤーと確定した装備をdigestへ含める。通信プロトコルは4、協力ルールだけを5へ更新する。

## 原作の構造と変更

構造名の照合に [th-re-data](https://github.com/exphp-share/th-re-data/tree/master/data/th12.v1.00b) を用い、アドレス・命令・呼び出し規約は所有する実行ファイルから確認した。以下のアドレスは通常版1.00a。通常版1.00bとSteam版1.00bのゲームコードは既存の検証済み `+0x20` レイアウトを使い、データアドレスと構造オフセットは共通。

| 対象 | 原作の構造 | 実装 |
|---|---|---|
| 機体・装備 | `0x4b0c90/94` の2つの共有変数 | actorの処理範囲で選択を切り替え、呼び出し終了時に復元 |
| 自機生成 | `Player::initialize` `0x435ac0` | それぞれの選択で元の生成処理を呼ぶ |
| ショット定義 | `Player + 0xa2c` のSHT | 個別にロード。P2生成時は前ステージのP1用SHTキャッシュを渡さない |
| 速度 | SHTから `Player + 0x990..0x99c` へ生成する通常・低速・斜め速度 | 原作の個体別パラメーターをそのまま使用 |
| 判定と吸引 | SHTの `+4/+8/+0xc` とPlayerの判定領域 | 個体のSHTから生成。衝突・アイテム処理は従来のactor選択を使用 |
| オプション | `0x438590` とSHT、機体別テーブル | 各actorの装備コンテキストで構築・更新 |
| アニメーション | `Player + 0x10` のANM。原作はslot 7を共有 | P1はslot 7、P2はslot 26。VM内のANM参照も独立 |
| ボム | 共有Bombの開始・更新・ダメージ・終了・破棄が機体共有変数でdispatch | 発動したactorの装備をラッチし、各dispatchへ適用 |
| ステージ・会話 | 原作は1つの機体ルートを選ぶ | `GameThread::thread_start` のロード前にP1の選択へ確定 |

ANM slotのポインターを描画時だけ交換すると、後から動くVMやエフェクトが別機体の画像を参照し得る。このためP2専用slotを使い、原作のANMローダーにslot番号を設定させる。

原作の明示的なslot 7参照は自機のロードと破棄にあり、射撃・ボムの生成にはactorのANMポインターを使う。slot 26は調査したローダー呼び出しで割り当てがなく、生成時にも空いていることを確認する。Endingが利用する28..31は使用しない。

P2破棄では元のデストラクターへP2のANMを渡し、そのVM・テクスチャ・SHTを一度だけ破棄する。ステージ遷移用にP1が持つANM/SHTキャッシュは維持する。P2は次の生成時に自分の装備をロードする。

機体・装備の共有変数を読む箇所は、自機とボムのdispatchのほか、ECLの共有変数取得、会話、GUI、スペルカード表示、スコア分類、メニュー、リプレイにある。これらの共有側はP1を基準とする。ステージワーカーは現GameThreadを参照し、ANM更新終了を待ってから資源をロードする。P2の初期化はそのロード内で行い、通常フレームの処理へ戻る前にP1の共有変数を復元する。デモ・原作リプレイの単独入力経路には機体選択を上書きしない。

予備機・ボム数・パワー・スコア・ベントラーは共有のまま。P2の生成処理による共有パワー上限・単位の上書きはP1の値へ復元する。製品の6装備は最大4段階、単位100であることを実ゲーム試験で検査する。ボムは同時に1回だけ有効で、開始失敗時には所有者と装備ラッチを元へ戻す。霊夢Aの後続ANMビームは既存の所有者・世代管理に装備コンテキストを加える。

EXTRA・Practiceの開放処理は変更していない。既存の `coop_progression::RefreshMenuAccess` がメニュー照会専用コピーの全6装備を開放する。元のスコア記録に書き込む方式ではない。

## 起動と検証インターフェース

通常ランチャーは起動前の機体指定を行わない。固定装備を必要とする診断呼出元だけが `Local\TH12CoopPlayers_<pid>` を使える。16byteのリトルエンディアン構造は `uint32 magic=0x43323154, version=1, p1, p2`。両方 `0..5` が必要。ゲームは初期化時に一度だけ読み、不在なら上記のゲーム内選択、存在する不正形式は起動拒否とする。固定装備の既存回帰テストとゲーム内選択のテストを分ける。

同期digestに選択、actorの速度・判定・SHT数値ヘッダー、ボムの装備を加えた。ANMやSHTのプロセスアドレスはdigestへ含めない。通常DLLから診断用状態変更機能を呼び出す経路は追加していない。

`Local\TH12CoopActors_<pid>` は144byteの観測用テレメトリー。ゲームは外部から書かれた値をゲーム状態へ取り込まない。先頭16byteは `magic=0x41323154, version=1, sequence, bombShot`。続く各64byteは `present, shot, anmSlot, powerLevels, powerUnit`、速度4個のint32、SHT半径3個と座標2個のfloat、`state, focus`。対応するactorが存在しないレコードはゼロ。ロックステップの入力待ち境界で読み取る。

`scripts/test_native_characters.py` は製品DLLへ確定入力だけを渡し、2つの隔離プロセスの全フレームdigest、機体、SHT、ANM、通常・低速移動量、双方の射撃とそれぞれが発動したボムの終了を照合する。判定半径は原作の機体別テーブルとも照合する。原作は敵の存在と自機タイマーを条件に低速移動を有効化するため、低速試験は通常入力でその状態になるまで待つ。標準は6組で両者の全6装備を含み、`--pairs all` は36組。`--mode extra` または `--mode practice --stage 2` などを指定できる。状態を変更するsmoke DLLは使用しない。音声とウィンドウの非干渉条件は `quiet_test.py` に従う。

パワーのあるステージでは原作ANMリストからslot 7/26の資源に属するオプションVMを読み取る。装備固有のスクリプト番号、パワー段階に対応した個数、両PCの座標一致、移動・低速操作による座標変化を検査する。観測時のパワーが0ならこの項目を未実施と記録する。

`--lifecycle` は同じプロセスでリトライ、タイトルへの解放、再入場を操作する。リトライ時のタイマー・ボム数・有効化回数、タイトル時の両actorとslot 26の解放、再入場後の装備・パラメーター・射撃を照合する。

新規hook4箇所の署名は通常版1.00a・1.00bの実ファイルで8/8一致を確認した。Steam版のディスク上コードは保護されているため同じ静的比較では判定せず、正規起動の早期フェンス後にRegistryが全署名を検査する。実ゲームで成功した組合せ・版・使用DLLのSHA-256と、未検証範囲は [検証結果](../verification/RESULTS.md) を参照する。入力試験だけで画像の目視確認や全ステージのクリアを確認済みとはしない。

共有ダメージの回帰試験（family 1 / case 3）は、診断専用DLL内でスペル番号93と有効フラグを一時的に設定する。元のfixtureはボスが存在しないまま有効フラグを残しており、ダメージ照合後の原作Spellcard更新がボスポインターを参照して停止し得た。この2つのスカラーをダメージ照合の直後に復元するよう修正した。変更は `COOP_SMOKE_TEST` 内だけで、製品DLLの挙動・ダメージ計算は変更していない。
