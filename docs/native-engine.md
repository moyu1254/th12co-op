# Native engine integration — cooperative rules 4

This document describes the current source architecture. The player-facing contract is [the cooperative rules](cooperative-rules.md); executed tests, binary identities and remaining coverage limits belong in [verification/RESULTS.md](../verification/RESULTS.md). An implementation description is not a claim that every stage, character, spell or ending has been exercised.

The native runtime has profiles for the inspected retail TH12 1.00a, retail 1.00b and Steam 1.00b executables. Preparation verifies executable/archive fingerprints; the launcher and injector verify the executable on each launch. The DLL checks the PE layout and every registered instruction region before installing hooks. `coop_patch::Registry` rejects mismatches and overlapping regions, prepares trampolines before code writes, and attempts rollback on a protection failure. The actual patch count is logged. Unknown profiles are rejected. Exact identities are recorded in [the version layout audit](version-layout-audit.md).

The original map was cross-checked against the installed executable, the [th-re-data reverse-engineering database](https://github.com/exphp-share/th-re-data/tree/41cd633354f3bbc4ff11b3d315ef7243c990f227), and [TH12 HFR development notes](https://github.com/vittorioromeo/th12_hfr/blob/45a7ecc4daedc3494bd7ef9211eb1c87073c5694/docs/games/TH12_DEVNOTES.md). Code addresses in this document use retail 1.00a notation: the gameplay functions/hooks after the insertion at `0x401720` move by `+0x20` in the verified 1.00b profiles; the score formatter at `0x401610` precedes it and is patched only on 1.00a, while globals, imports, vtable locations and object offsets stay unchanged. `game_layout.h` selects this translation from the verified runtime profile. The complete shifted code range and data sections were compared; this is not an assumed universal offset for other builds.

Native update nodes are enabled and disabled by the game's stage and pause lifecycle. P2's separately registered nodes are removed after construction; P1's tick/draw callbacks own both passes. This avoids updating P2 during a pause or leaving its nodes disabled at stage start. The activation function has four direct call sites in stage/reset and pause retry handling; individual death and respawn remain in each actor's native tick state machine.

Character/shot dispatch globals are scoped to each actor. Each actor owns an independent native SHT and ANM allocation; P1 uses ANM slot 7 and P2 uses checked spare slot 26. Bomb dispatch retains the initiator's selection through completion/destruction. Power, bomb stock, score, fragments, item value and UFO inventory remain shared. Story and ending selection use P1. See [independent character integration](independent-characters.md). The original replay format contains one input stream, so cooperative replay saves are rejected. Demos and original replay playback create one actor and retain native single-player paths.

## Resources, aiming, collection and ownership

`coop_resources.h` treats displayed lives as shared reserves. A committed miss consumes a reserve and records a respawn credit for that actor. Without credit, the actor remains in native dead state 2 and waits while its partner continues. New reserves go first to waiting actors in fixed P1/P2 order. Game over occurs only when both cannot return and the native miss animation delay has elapsed. Native activation at stage checkpoints, retry, continue and new runs resets the relevant credits and actor state. Actor eligibility is native state 0 or 1, excluding an issued game over.

Time-based rank increments happen once. Each committed miss retains native power/rank/spell consequences, but the death-time shared bomb refill is suppressed. Start/retry/continue initialization and item refills remain native. A bomb consumes one stock and starts once; P1 wins simultaneous requests because its tick runs first. Its invulnerability protects both eligible actors and can rescue a partner inside the native deathbomb window. Direct global bomb damage is evaluated only in the owner's pass. Native respawn and spell reductions are applied to each actor's contribution before summing damage.

Bomb ticks and transition-time cancellation preserve the initiator, including Reimu B's cancellation explosion sources. `coop_effects.h` additionally stores owner IDs and actor-generation tags in delayed Reimu A emitter/beam payloads. Later callbacks use that owner instead of the current bomb initiator. Activation retires old beam sources and invalidates their generation; destruction never dereferences sources belonging to freed actors. Original VM destruction frees the extended payloads.

`coop_collision.h` checks both eligible actors before returning a combined result. The original projectile/laser caller awards team graze once per native opportunity; effects appear at the actor that actually grazed, with P1 winning simultaneous ties. Laser cancellation uses the actual hit position and handles both positions when both actors are hit. Waiting actors cannot graze. Custom register-ABI calls use non-inlined C++ adapters to keep volatile register clobbers visible to the compiler; hook sites with live floating-point values preserve that state explicitly.

`coop_targeting.h` selects the nearest eligible actor to the enemy/shooter origin, with P1 winning exact ties. One ECL execution and its nested volley share a frozen target. Native retarget commands outside that scope choose again when executed; existing straight bullets are not redirected. Aiming reads use a separate scoped pointer and do not replace the actual owner for damage, items, bombs or lifecycle. Spawn-distance rejection considers either eligible actor. If neither is eligible, transitional aiming falls back to the original/P1 actor.

`coop_homing.h` maintains native target/lock fields separately for both actors and preserves the executable's comparison order. Enemy destruction and the other native release path clear matching actor targets and all 256 shot target pointers for both players. `coop_force.h` applies the player-local scripted force portion to both eligible actors through the native position writer, then runs the shared bullet loop once. Dialogue transition flags and option interrupts are also applied to both actors without running the dialogue VM twice.

`coop_items.h` separates motion ownership from physical pickup. Either eligible actor above native Y=128 can trigger POC even when the nearer actor is below it. Focus attraction uses each actor's consumed input and native rectangle. Attracted items latch an owner ID and retarget when that actor becomes unavailable. After movement, pickup tests the union of both eligible rectangles and enters one native award branch. Slot initialization, activation and manager changes clear stale ownership. With no eligible actor, player attraction and player-dependent POC/apex/token proximity branches stop; ordinary motion and existing large-UFO suction continue. UFO inventory, spawning, absorption, food and rewards remain shared and execute once. Native collector-height scoring and paired power-option updates are retained. See [the item/progression audit](audit-items-progression.md).

`coop_progression.h` adjusts lower counters, upper boss labels, the bottom boss marker and spellcard overlay for either eligible actor. Shared portraits, menus and team hints remain single displays. Extra for all six shot choices and Practice stages 1–6 at all four ordinary difficulties are available offline and online through a menu-only Scorefile query view. Both cursor eligibility and visual/confirmation queries use that view. The real Scorefile is not given fake clear flags. Record writes remain one team stream in the isolated copy; online starts fresh records each session. Original installed records are preserved.

## Startup and online frame boundary

Both peers load known executable profiles with the same game engine version, cooperative rules **6**, assets, MOD, local optional-dependency identity and normalized shared configuration. Local display/audio/input configuration may differ. Retail 1.00b and Steam 1.00b may pair because the authorized Steam runtime game code and static data match retail 1.00b. Each peer's distribution ID must match its known executable hash. Retail 1.00a and 1.00b cannot pair. Protocol 4 carries the build/dependency identity, rules number and both players' selections; invitations use `T12L4`. Each PC renders and plays sound locally. No video or audio is sent. See [configuration isolation](local-configuration.md).

`coop_visuals.h` filters only the remote actor's focus-marker VM at the native ANM draw entry. The local actor is supplied by the launcher's own host/guest role at IPC +120. The remote actor's body alpha is multiplied by 112/255 for the draw call and restored before returning. Marker IDs, focus state, animations, collision geometry and gameplay fingerprints remain unchanged; offline draws both markers. Read-only `TH12CoopVisuals` observations count native draw/skip decisions and the submitted body colors.

Both offline and online games are created suspended. The injector parks the primary thread at the verified executable entry point (`0x46E7FD` for retail 1.00a, `0x46E81D` for retail 1.00b, `0x4D9310` for Steam 1.00b) while Windows finishes import loading, suspends it again, restores the original bytes, and loads the DLL through the resolved remote x86 `LoadLibraryW` address. `Local\TH12CoopBoot_<pid>` supplies verified primary-thread metadata independently of network input. Missing or invalid metadata is rejected. Retail hooks install before the launcher resumes the primary thread. There is no ordinary offline title-screen injection path and no executable file on disk is patched.

Steam startup uses a two-phase fence in both modes because game code is still wrapped. The DLL arms the `timeGetTime` import at `0x498298` and publishes status 5, meaning armed rather than ready. The launcher resumes normal Steam startup. Only the game's first seed call, with return address `0x42F588` on the primary thread verified by boot metadata, triggers installation. The callback restores the import, verifies/installs game hooks and returns the original clock value offline or the agreed seed online. Other clock calls pass through. Device readiness is published only after installation; thread/import/signature failures stop startup for cleanup. Normal Steam authentication remains in place, and no unpacked executable is written. Online header offset 92 must agree with the boot thread ID.

`Supervisor::on_tick` at `0x42EFE0` calls the raw input poll `0x462EA0` once at `0x42F012`, before gameplay callbacks. The hook at `0x4631E2` replaces the polled mask before native edge/repeat derivation. Online inputs are frame numbered in a bounded IPC ring; a missing frame stalls simulation and a protocol error stops it. Offline input behavior remains native.

Initial RNG seeding is the `timeGetTime` IAT call at `0x42F562` (`FF 15 98 82 49 00`). Online sessions substitute the agreed seed before the native writes to replay RNG `0x4CE568` and animation RNG `0x4CE560`. Each RNG contains a 16-bit seed at +0 and a 32-bit consumption counter at +4. Offline mode calls the original clock. Replay restoration and the native RNG algorithms are retained.

The engine unconditionally enables its synchronization flag `0x8000` at `0x44F58B`. It is not a configuration option. Native critical sections remain enabled. The stage worker starter `0x4304E0` records its worker handle (`0x4CF0DC`); the next raw poll joins it before hashing or advancing the next simulation frame. Joining immediately inside startup would prevent required rendering/resource work. The bounded wait services the original ANM upload dispatcher `0x4603B0` and audio command dispatcher `0x453F80`, normally called by the supervisor. It does not run world simulation while waiting.

The initial LoadingThread at `0x42E990` also initializes the score file (`0x43D030`), consuming gameplay RNG on a worker thread. Its handle at `loading+0x14` is joined before publishing a frame digest. This is necessary even with a shared seed: otherwise peers advancing a few frames apart can observe different points in that initialization.

MainMenu's worker at `0x43F300` waits for the LoadingThread draw counter at `+0x4F4` to reach 180, then enables the menu callback. The online gate joins the worker handle at `menu+0x5C20` after that threshold, eliminating the worker's `Sleep(16)` activation race. The shared configuration disables frame skipping (`cfg+0x1E = 0`), so the normal `0x4503D0` and `0x4505E0` frame paths each perform one draw per update.

The digest compares selected gameplay fields without process-dependent pointers: shared counters, replay RNG, both actors and shots, enemy positions/health and normalized primary/async ECL instruction locations and initialized scalar fields, enemy bullets and behavior data, items, lasers and curved laser trails, menu and pause state. It includes cooperative resource credits/wait/game-over/bomb ownership, item owner IDs, targeting/collision state, input history, native homing state and live delayed bomb effects. Enumerated target/damage-source references are normalized to indices; this does not include every native homing association. The Rules3 additions cover RA beam history, UFO/token/reward scalars, selected active bullet Ex timers/operands and the common laser Ex instruction index. See [the projectile audit and remaining gaps](audit-projectile-digest.md). Main scene metadata comes from `0x4CEE3C`.

Enemy list entries are full `zEnemy*`: data starts at `+0x1040`, verified by `0x41318E` and the HP store at `0x4129C8`. Conflicting public annotations do not override these instructions. Raw ECL stack contents remain outside normalized coverage: typed tags leave padding uninitialized, and local reservations do not initialize every word. Async contexts include verified time, instruction location, stack/base offsets, ID and difficulty; uninitialized async flags are excluded. Subroutine locations use stable table-row identity plus byte offset. The final subroutine has a numerical range cap rather than exact file EOF validation. The FNV-64 digest detects divergence in enumerated state; it is not a complete memory snapshot or anti-cheat proof. See [the IPC contract](native-ipc.md) for sequences, deadlines and failure behavior.

## Diagnostic build boundary

The normal DLL excludes the smoke raw-menu-input override and `TH12CoopAudit` command mapping. The separate smoke DLL supports input-driven scripts whose process-memory access is observational, and destructive audit fixtures that deliberately set positions/resources/states or spawn native objects on the game thread. Campaign fixtures additionally grant invulnerability/power and multiply damage while retaining native timing, ECL and stage progression. These are distinct test methods; Python writing only an audit command does not make the resulting fixture non-mutating.

Use disposable game copies and close each fixture process afterward. Accelerated invulnerable runs are progression/lifetime evidence, not normal-difficulty playthroughs. Source/fixture availability or compilation alone is not a runtime pass. Only [recorded verification](../verification/RESULTS.md) establishes which binaries and paths were exercised.

## Rules 5 damage and selection

`coop_damage.h` batches accepted damage at the native pre-HP boundary within one enemy-manager tick. Original native stacks resume in list order after category-wide shot ratios are sealed. `coop_damage_sources.h` tracks native non-shot provenance, and `coop_damage_budget.h` owns bounded integer history/rounding. The scalar state enters the existing lockstep digest. The production DLL accepts no diagnostic state writes. See [the damage design](cooperative-damage.md) for source/cap attribution, phase resets, addresses and verification scope.

Normal launches omit fixed startup equipment. `coop_characters` reuses native menu states 6/7 for sequential P1/P2 choices, including the distinct Practice confirmation path; `coop_progression::MenuTick` publishes the native player label and restores P1's story route after both confirmations. Fixed startup equipment remains a diagnostic adapter. [Independent characters](independent-characters.md) describes selection cancellation and lifetime behavior.
