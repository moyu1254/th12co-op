# v0.1.1の追加監査

対象は初回リリースのコミット `400c4b7` と、検証用に所有する通常版1.00a・1.00b、Steam版1.00b。指摘を実装へ機械的に適用せず、原作の命令列、初期化処理、専用の境界診断、製品DLLの同期試験を分けて確認した。実行結果とバイナリ指紋は [v0.1.1の検証記録](../verification/audit-v0.1.1/RESULTS.md) に記載している。

## 確認した問題

- 1.00aの10億点表示は未初期化文字列をキューへ渡していた。公式1.00bと同じ4群の表示を1.00aだけ補い、得点の計算・上限は変えない。終端付きの診断文字列による再現であり、ランダムなクラッシュを実測したとは扱わない。
- 2Pの喰らいボムだけ、先に更新された1Pの猶予7→8を救済できなかった。共通フレーム開始時の猶予を使い、確定したミスは戻さない。
- 同期検査に将来の挙動を決める状態の欠落があった。霊夢Aのビーム履歴、ECLの命令位置と並行context、アイテム・UFO、敵弾のExタイマー・数値パラメーターとレーザー命令位置を正規化した検査へ追加する。ポインターや未初期化の領域をそのままhashしない。
- 初期ファイル作成の中止、セッション準備の失敗、接続待ち中の資産変更、準備中の切断、期限切れの表示、停止理由の上書き、診断保存の失敗による例外の隠蔽を修正する。

原因・番地・試験条件は [資源とECL](audit-resources-followup.md)、[アイテムとUFO](audit-items-recheck.md)、[弾と入力](audit-projectile-digest.md)、[ランチャーと通信](audit-managed.md) に記録する。

## 変更しないと判断した処理

| 項目 | 確認結果と扱い |
|---|---|
| 回収状態とベントラー | 生存者への回収先引継ぎ、対象不在時の報酬payload保持、近接による色変更停止、二重取得防止は追加診断で正常。両者が回収不能の際の吸引解除は原作にもある。既存の上部回収への昇格ルールを維持 |
| UFOと2人の威力 | 原作の吸収・満腹ボーナス・報酬を1回ずつ処理。2人の通常威力で早く倒せることは既存ルール。HPや報酬倍率の独自補正は追加しない |
| 共有資源と復帰 | 共有予備機、個別の復帰権、待機者へのエクステンド、面開始の復帰、死亡時にボムを補充しないルールを維持 |
| 聖・ぬえの特殊防御 | 原作のスペル番号・無敵・ボム条件を追跡。原作にあるダメージ制限を削除する根拠は得られず、現行の各自機への補正と敵側の共有判定を維持 |
| 魔理沙Aのレーザー | 自機ごとのnative処理、4フレーム間隔、判定形状を保持。全パワー段階・全ボスを実戦で通過したという主張はしない |
| ANM排他 | 原作が使用するcritical sectionと一致。別スレッドの進入阻止、再帰取得後の解放、カウンター復帰を診断。再現していない競合を確定不具合として扱わない |
| 照準・入力・互換性 | 近い行動可能自機、斉射中の固定、各自機の入力・衝突を維持。既知3プロファイルのみ許可し、未知のEXEへ推測したパッチを当てない |

## 残る検証範囲

状態digestは列挙した状態の差を検出する仕組みで、完全な状態保存や不正改造対策ではない。ECLのraw stackには未初期化の型タグ上位byteや未初期化local領域があるため、全体の比較を追加していない。最後のsubroutineはファイル終端を保持する情報がないため数値上限で検査する。新しい上限はMODの防御的な処理量制限で、原作の正式な最大値ではない。敵弾の寿命・グレイズ等の一部状態、レーザーの種類別内部状態、nativeホーミングの敵参照などにも未収録の状態が残り、差の発生と同時に必ず検出できるとは限らない。[未収録範囲](audit-projectile-digest.md#coverage-limits-retained-explicitly)を明示する。

全難易度・全スペル・全自機の全パワー段階を新バイナリで完走したものではない。Extra/Practiceの開始と短時間の同期一致は、それ以降の全ステージ進行を保証しない。WAN、別PC、ネットワーク機器ごとの挙動も別途検証が必要。旧版で実施した無敵・威力補助による全ステージ診断は、旧版の記録として区別する。
