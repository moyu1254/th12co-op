# 共有リソースとプレイヤー状態の監査

2026-10-29の監査記録。根拠は検証用に所有する retail 1.00a / 1.00b の実行ファイル、`research/th-re-data` の構造体定義、および監査時点の MOD ソース。以下のコード番地は 1.00a。1.00b の対象コードは +0x20、グローバル番地・構造体オフセットは共通。Steam 版の動作検証結果は別の検証記録に従う。

## 採用する協力プレイルール

| 対象 | ルール |
|---|---|
| 自機 | 2つの独立した native Player。位置、ショット、被弾猶予、復帰時間は個別 |
| 残機 | HUD はチームの予備機数。ミス確定時に予備があれば1つ消費し、その人の復帰権を確保 |
| 予備機なし | 倒れた人だけ待機。非表示・射撃不可・回収不可・グレイズ不可。相方は継続 |
| 全滅 | 両者とも復帰権がなく、native の死亡待機30フレームが終了してからゲームオーバーを1回発行 |
| エクステンド | 待機者を P1、P2 の順で復帰させ、余剰を予備機として保持。native の加算上限8を保持。Practice の開始設定では9になる場合がある |
| ステージ開始 | 両者を native activation で復帰。チェックポイントの報酬として予備機は減らさない |
| リトライ・コンティニュー | native の共有リソース初期化を使い、両者の状態と MOD の復帰権を初期化 |
| パワー・ボム・スコア・PIV・UFO | チーム共有。アイテムは1回だけ精算 |
| 死亡ペナルティ | 確定ミスごとに native のパワー低下・パワーアイテム放出・ランク低下・スペル失敗を実行 |
| ボム補充 | 死亡では補充しない。開始・リトライ・コンティニューの native 初期値2と、通常の回収による補充を保持 |
| 同時ボム | native のボム管理オブジェクトは1つ。固定更新順に従い P1 優先。消費は1回 |
| 喰らいボム | 発動成功時、両者の native 8フレーム猶予内の被弾を救済。確定済みのミスは戻さない |
| ボム無敵 | 発動者と生存中の相方を保護。相方のより長い復帰無敵は短縮しない |
| ダメージ | 各自のショット・ダメージ源を1回ずつ評価。直接ボムダメージは発動者の評価だけに含める。死亡・登場中・特定スペルの無敵補正は各自に適用 |
| グレイズ | native の弾単位・レーザー間隔単位の上限を保持し、チームとして1回精算。同時接触は被弾判定を優先 |
| ランク・時間 | 時間は既存の管理者が1回進める。Player 内の定期ランク加算は P1 更新だけで実行。各人のミスによる低下は保持 |

## 実行ファイルから確認した問題と対応

| 確認事項 | 根拠 | 対応 |
|---|---|---|
| Player を2回更新するとランク加算も2回起きる | `4374DC–43751D` | 加算命令だけ P2 で抑止。P2 更新後にランク全体を書き戻す方法は使わない |
| 最後の1機を消費した人と、予備なしで倒れた人を区別できない | `4381C7` が共有残機を減らし、`436E80` が共有値だけで復帰を決定 | 個別の復帰権を確定ミス時に記録し、復帰分岐を置換 |
| 生存中の相方がいても共有値が負ならゲームオーバー | `436E88–436EA3` | 両者の状態・復帰権・死亡待機時間を確認 |
| 両者の死亡復帰でボムが2へ補充される | `436EEF → 422F40` | coop 時のみ補充 setter を抑止。開始等の初期化とは別経路 |
| 元のダメージ関数を2回呼ぶと直接ボムも2回入る | `439EB0 → 406DC0` | 発動者以外の pass では直接ボムの寄与だけ0にする |
| 1P の死亡・登場補正が合算後の2P攻撃にもかかる | `413D78–413D99` | 各 actor の戻り値に個別適用してから合算 |
| スペル93–99で1Pの無敵状態が2Pの攻撃も下げる | `413DB7–413DF9`, `412670` | 同じ native 条件を各 actor に適用してから合算 |
| ボムの無敵延長は singleton の actor だけ | `406F40` と6機体の呼び出し | 相方にも適用。初期化で直接タイマーを書く機体も発動 hook で補完 |
| 待機 state2 でも geometry の外側グレイズ分岐は通れる | `4378D9–43794D` ほか | collision 呼び出し側で対象を state0/1 に限定 |
| 霊夢Aの遅延ボム攻撃が通常の Bomb tick の外で生成され、P1へ所属する | `46A623 → 40FBC0(type4)`、後続 `46A3BE/46A433 → type3 → 469837` | 演出の native payload に発動者と世代を保持し、子の攻撃判定を発動者へ固定 |

`coop_resources.h` がリソース処理を所有し、main が生成・破棄・activation・各自の tick・damage に接続する。パッチは全署名を検証してから一括適用する。非 coop のデモ・リプレイでは元の分岐を保持する。

オフライン・オンラインとも、ランチャーはゲームを停止状態で生成し、既存 injector の実行開始点待機を通してからパッチを適用する。16バイトの起動メタデータでメインスレッドを確認し、製品版 DLL と smoke DLL の両方で、起動情報のないオフライン後付けを拒否する。Steam は通常の初期化が seed 呼出点へ到達したメインスレッド上で適用する。ウィンドウ表示後の動作中スレッドへ多バイト JMP を書き込む経路を使わない。

## 状態と呼出規約

Player `+A28` は state0=登場・復帰、state1=通常、state2=確定ミス、state4=8フレームの被弾猶予。state3 の更新分岐は存在するが、この調査で直接代入元を特定していないため、回収対象へ含めない。state2 は native 描画で非表示、native 射撃は state1 のみ。待機者の既存ショット・ダメージ源は native の寿命更新を続ける。

| 関数・分岐 | 呼出規約・意味 |
|---|---|
| `4381C0` | ESI=Player、引数なし。死亡演出・残機減算・スペル失敗・ランク低下 |
| `436E7E` | Player tick 内 EDI=Player。30フレーム後の復帰／ゲームオーバー分岐 |
| `422F40` | EAX=Globals、引数なし。死亡復帰専用のボム2補充 |
| `406BD0` | cdecl 引数なし、0=ボム開始成功、-1=既に実行中 |
| `406F40` | stdcall(int frames)。singleton の無敵タイマーを設定 |
| `406DC0` | EDI=敵座標、stack=敵サイズ、callee pop4。直接ボムダメージ |
| `439EB0` | stdcall(position,size)。actor の弾とダメージ源、直接ボムを合算、actor 単位の上限80、ヒットスコア |
| `4390D0` | EAX=Player、stack=(position,radius,angle,duration,damage)、callee pop20。native damage source 作成 |

全6機体の喰らいボム受付は共通の Player 分岐。ボム管理更新は Player priority16 の後の priority17。Reimu A/B と Sanae B の主要ボム攻撃は actor のダメージ源等を使い、Marisa A/B と Sanae A は `406DC0` の直接寄与も持つ。敵HPの減算・撃破処理は合算後の既存の敵更新が1回処理する。スコア・PIV・ボム欠片・残機欠片は元のグローバル操作を使う。

## 残る確認と検証方法

本書は静的監査と実装内容を記録するもので、実行試験の合格宣言ではない。新仕様の実行結果は root が管理する検証レポートで確認する。

`coop_audit_resources.h` は smoke ビルド専用。両者が通常状態かつボム未発動のステージ中、メインスレッドから `RunResourceAudit(caseId, details[32])` を1回呼ぶ。失敗ビットが0ならその fixture の条件が成立した。必ずケース・機体ごとに新しいプロセスを使用し、結果取得後に終了する。native VM・アイテム生成の副作用をメモリ復元で巻き戻したとは扱わない。

| Case | native 関数を使う確認 |
|---|---|
| 0 | 最後の予備機の割り当て、相方の待機、エクステンド復帰、死亡ボム補充なし |
| 1 | 予備機0でも相方が継続、両者の30フレーム後だけ全滅、ゲームオーバー重複なし |
| 2 | 同時喰らいボム、両者救済、消費1、相方の長い無敵を保持。全6機体で実行 |
| 3 | native damage source 10+20=30、1P登場・死亡中は2+20=22、特定スペルの1P無敵も2+20=22 |
| 4 | P2が発動した直接ボムの寄与が native 1回分と一致。全6機体で実行 |
| 5 | 両者が同じランク加算周期を迎えても共有ランクは+1 |
| 6 | P2の Reimu B ボムを切替時に終了しても、8個の終了爆発のダメージ源はP2へ所属。P1には生成しない |
| 7 | P2の Reimu A 遅延攻撃はP2へ所属。共有ボムの現在所有者を試験で変更しても所属が変わらず、activationで旧攻撃を終了し、旧世代の子は無効な攻撃ポインタに触れない |

Reimu B の切替時終了関数 `406EB0` は通常の Bomb tick の外から呼ばれるため、所有者を固定する専用 hook を追加した。Reimu A は `coop_effects.h` で type4 emitter の割当・ゼロ初期化を `0x30→0x38`、type3 beam を `0x418→0x420` に拡張し、末尾に actor ID と世代を保持する。native VM destructor `4026C0` が元どおり payload を解放する。type3/4 の on_destroy は空の戻り処理で、攻撃判定への参照はない。actor の再生成は世代だけを無効化し、activation は生存する actor 内の確認済み範囲にある旧 beam 判定を終了させてから世代を無効化する。

Reimu A の同期ダイジェストは native world/UI VM リストから該当 callback の現世代 payload のみを選ぶ。所有者ID、座標、確認済みタイマーと幾何情報、actor 内の攻撃判定番号を含め、VM・payload・速度・攻撃判定のアドレスや無関係な描画演出は含めない。damage source・ボム・スペル・ランクも、コンストラクタのゼロ初期化とスカラー参照を確認している。これらでゲーム状態の全量を正規化したとは扱わない。

MSVC最適化時のネイティブ特殊ABI呼び出しは、`noinline` の独立したC++呼び出し境界に置く。inline asm 内の `call` だけではコンパイラがXMMレジスターの破壊を認識せず、呼び出し前の値を再利用する場合があるため。資源処理では死亡・状態タイマーのアダプターと、fixtureの特殊ABI呼び出しへ適用した。
