# 協力ショット補正（Rules 5）

原作のHP・敵数・弾幕・攻撃間隔は変更せず、有効なショットダメージだけを制限する。次の値は初期値。撃破時間やパターンの実測を蓄積して調整する。

| 区分 | K | 履歴 |
|---|---:|---:|
| ボス通常・スペル・中ボス | 1.20 | 60ゲームフレーム |
| 道中の通常敵全体 | 1.25 | 30ゲームフレーム |
| 大UFO | 1.00 | 30ゲームフレーム |

直近Nフレーム（当該フレームを含む）の補正前の有効ショットダメージをプレイヤー別にD1/D2へ集計する。S=D1+D2。S=0なら倍率1、それ以外は `min(1, K * max(D1,D2) / S)`。ボスの100:100、100:50、100:20は合計120、100:0と0:100は100になる。入力ビット・発射数・装備名から寄与を推定しない。

## 同一フレームの確定

過去フレームだけで倍率を決める方式は、最初の両者命中を200%で通してしまう。対象ごとの呼び出し中に履歴へ加えて倍率を決める方式も、別々の敵への初撃や対象の列挙順で結果が変わる。どちらも採用しない。

`EnemyManager::on_tick` の中で、各 `EnemyData::on_tick` を原作の衝突判定・ダメージ制限後、HP適用前の境界まで一度だけ実行する。境界に到達したネイティブのスタックを同じスレッドのfiberで保持し、全対象の寄与がそろってから区分ごとの共通倍率を確定する。その後、元のリスト順で各スタックを再開し、原作のHP適用、フェーズ割込み、ヒット演出、死亡処理を実行する。衝突の再実行、翌ゲームフレームへのダメージ持越し、HPの後付け補修は行わない。

保留中は原作の「当該敵を更新中」ビットを維持し、再帰更新を防ぐ。managerのステージタイマーの加算も全件再開後に行い、敵のECL・死亡処理へ次フレームの時刻を見せない。fiberは同じゲームスレッドで再利用する。新規fiberの初期FPU設定は呼出元と異なるため、各呼出しで呼出元のx87/MXCSRを明示的に引き継ぎ、終了時の状態も戻す。フレーム境界までに全件が完了する。確保失敗や4096件の上限超過で未補正へフォールバックせず、その所有ゲームを終了する。オンライン入力待ち境界に未完了のfiberは持ち込まない。

原作は敵の生成中にも、idの割当て・リスト登録より前に `on_tick` を呼ぶ。この経路や再帰呼出しで未集計のショットを消費させない。移動・ECL・ボムは実行し、ショットの命中判定はmanagerの通常更新まで保留する。そのため生成直後のショット命中時刻は原作と異なる場合がある。次フレームへのHP返金ではないが、原作との撃破時刻・早回し比較で確認する必要がある。

この変更は協力プレイ時だけのダメージ処理の順序変更を伴う。原作の敵更新全体が不変であるとは扱わず、撃破時刻・早回し・ボス割込みの実ゲーム比較を検証項目に残す。原作の重なった標的に対する弾の消費順序は維持する。

## 有効ダメージとボムの区別

- 原作の弾・damage sourceの命中処理を各actorにつき一度だけ実行し、命中スコアや弾の消費を二重実行しない。
- damage sourceの生成元を記録する。魔理沙B、早苗Bのボム、霊夢Aの後続ビーム、復帰波を非ショットとして保持する。通常弾・オプション・ホーミング・早苗Bのショット爆風はショット。
- 原作の直接ボムダメージは従来どおり発動者のpassだけで評価する。ボム終了後も残るsourceの分類は生成元を保持し、slotの再利用時に更新する。
- actorごとに原作のquery上限80、extended callbackの圧縮、復帰・死亡状態の1/5、スペル93～99の自機別1/5、スペルflagsの最終1/30を原作の順序で適用してから、協力倍率を計算する。1/30を両者の合算後に適用すると、原作で双方15→0の攻撃が合計30→1になってしまうため、合算前に丸める。
- 同じ制限を「ボムだけだった場合」にも適用し、その原作ダメージを非ショットの基準として残す。合計との差分だけを補正し、混在時もボムの基準ダメージを削らない。
- 敵の無敵・GUIのダメージ禁止・スペル103～112のボム耐性・スペルflagsによる1/30制限を通った、HP適用可能な寄与だけを履歴へ入れる。
- ECLのextended damage callback（テーブル `0x4af118`）は31点の合算を非線形に圧縮する。原作の圧縮をボム単独の基準にも適用して差分を求める。このcallbackはUFO識別子ではない。
- UFOは原作UFO managerの有効な所有Enemyポインターとenemy id、ボスは原作のbossフラグで区別する。通常敵は全対象を同じ履歴に加える。

## 履歴・端数・決定性

履歴は3本のリングバッファ。命中のないフレームも進め、最後の命中からNフレーム後には必ず失効する。ポーズ中の実時間は数えない。両方が原作state 1でない間、および両方が行動可能へ戻った境界では履歴を破棄して倍率1へ戻す。開始・復帰後の初めての両者命中も、同一フレームの合算で初期補正する。

自機の再生成・原作activation・ステージ移行で初期化する。ボス登録、最大HP、スペル分類の変更と、HP再設定による増加を攻撃フェーズの境界としてボス履歴を初期化する。UFOも新しい所有enemy idで独立に初期化する。

計算は整数とQ16。倍率は丸めた0.60などを先に掛けず、整数比のまま保持し、x86でも積がオーバーフローしない筆算の除算で適用する。HPへ渡せない端数は原作の安定したenemy idごとに保持する。命中の途切れで捨てず、敵の消滅時に解放する。対象間の共通端数を先着順に配る方式は使わない。

履歴、端数、フェーズ、自機の行動状態、source分類を同期digestに含める。fiber、SHT、Enemyなどのプロセスポインターは含めない。オフラインとオンラインは同じ計算経路。原作デモ・リプレイではネイティブ経路へ委譲する。

## 接続箇所（通常1.00a）

| アドレス | 用途 |
|---|---|
| `413170 / 413820` | managerと敵の更新境界 |
| `41319d / 413e60` | 更新中フラグとHP適用直前 |
| `4131c1` | ステージタイマーの更新境界 |
| `43918b` | sourceの生成元 |
| `43a1de / 43a3b1` | 直接ボムとsourceの実命中量 |
| `439f50 / 43a1fc` | 通常更新以外でショットを消費しないための判定 |

通常1.00b・Steam1.00bは検証済みのコード差分+0x20を使用する。ボス登録先は `Enemy*` であり `EnemyData*` ではない（`417b09..23` の登録と `40dc30..39` の消費を照合）。機体表示に使う `AsciiManager::create_string` は差分挿入より前のため、両版とも `4014f0`。

`verify_damage_layout.py` は既知のSHA-256を持つ通常2版で新規12箇所の署名、source呼出元6箇所、上記のボス登録とASCII関数を読取専用で照合する。Steamは保護されたディスク上コードを推測せず、正規起動後のRegistryと実ゲームで確認する。

## 検証インターフェース

`Local\TH12CoopDamage_<pid>` は288byteの観測専用データ。外部の書込みをゲーム状態へ読み戻さない。先頭48byteは12個のuint32（magic=`0x44323154`, version=1, sequence, frame, activeMask, bossEpoch, stage, bossId, maxHp, spell, ufoEpoch, ufoId）。続く3組各48byteは `shot1,shot2,native,applied,bomb` のuint64と、Q16表示倍率・対象数のuint32。最後の各32byteは区分別の累積native/applied/bomb/対象数。

`test_native_damage.py` は実命中を読み取り、Python側の独立した履歴計算と倍率、全フレームの両PC digestを照合する。`--ufo-fixture` は診断DLLで原作のUFO生成、Powerと自機無敵を準備する。UFO自体のHP・軌道・死亡処理は変更しない。`--campaign-fixture` はPowerと自機無敵だけを準備する。通常の入力試験と診断試験を記録で分離する。ビルド時の `damage_budget_test.cpp` は提示例、原作の制限順序、区分、順序・actor対称性、期限、行動不能、端数、整数積の上限を検証する。`fiber_fpu_test.cpp` は新規・再利用fiberへの呼出元FPU設定の継承を確認する。

履歴倍率は、指定された式のとおり「現在フレームを含む過去Nフレームの寄与比」を使って現在のダメージへ掛ける。過去の補正済みダメージを再精算する方式ではない。途中から片方の命中量が急変する場合、現在フレームの合計がその瞬間の強い側のK倍を超える、または下回ることはある。無履歴・フェーズ開始時の200%と、期限を超えた残留減衰は防ぐが、任意のNフレーム区間の補正後総量をK倍へ固定する保証とは区別する。この挙動を含めた体感・撃破時刻の調整は検証記録の未検証範囲とする。

最終的な撃破時間、全装備・Power、全スペル、別PC/WANの確認範囲は[検証記録](../verification/rules5/RESULTS.md)を参照。
