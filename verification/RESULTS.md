# 検証結果 — 協力ルール2

検証日：2026年10月29日（JST）。Windows上の隔離コピーで実施。対象は通常版1.00a・通常版1.00b・Steam版1.00b。今回のバイナリとソースの指紋は `binaries.json`。旧ルールの実行試験を今回の結果として流用していない。

## ビルドと起動

通常DLL・検証専用DLL・ローダーはx86、ランチャーはx64/.NET10.0.14自己完結版。通常DLLとランチャーはビルド成功。検証専用DLLには診断用アセンブリのC4740警告が1件あり、その関数の最適化だけが抑制される。

各版で停止状態から通常DLLを読み込み、描画準備完了まで起動。重複起動は既存プロセスと設定を変えず拒否。通常終了に加え、Stop/Disposeを呼ばずランチャーを終了する独立試験でも所有ゲームが終了した。Job Objectは所有ゲームだけを登録する。

Windows PowerShell5.1で配布スクリプトの構文とUTF-8 BOMを確認。元インストールのEXE・DAT・BGMは既知の指紋と一致。記録は版別の `startup.json`、`startup-guard.json`、`owner-exit.json` と `powershell.json`、`installed-assets.json`。

## 原作との接続と境界条件

自機の直接参照116か所を分類し、照準・衝突・資源・アイテム・演出・進行へ追跡。登録パッチの命令列を通常版1.00a/1.00bに照合。Steam版は正規起動後のゲームコードが1.00bと一致することを事前に確認済みで、今回も起動と実ゲーム試験を実施。コンパイル後の独自呼出規約アダプターを検査し、P1呼出後の浮動小数点レジスターをP2判定へ誤って再利用しないことを確認。詳細は `native-static.json` と `../docs/audit-*.md`。

通常版1.00bで31件、1.00aとSteam版で重要な5件ずつ、計41件の実ゲーム診断を実施。予備機・待機復帰・被弾直後ボム・6装備のボムとダメージ・ランク・照準固定・円/矩形/レーザー衝突・ホーミング参照・強制移動・上部回収・低速吸引・接触優先・回収先固定/再選択・UFO・会話/HUD・Extraの利用可否・霊夢の遅延攻撃所有者を検証。全件成功。記録は `rules/`。

これらは専用DLLで原作状態を意図的に作る診断であり、自然な通常プレイだけの結果ではない。専用DLLと診断IPCは配布バイナリに含めない。

診断用DLLは2ビルドを使用した。41件の境界診断・オフライン・モード試験は最初のビルド、後述の面進行と重要5項目の追加回帰は修正後のビルド。修正は診断専用のタイマー加速の撤去だけで、通常DLLのプリプロセス後の有効コードと製品バイナリは同一。指紋と用途は `binaries.json` の `diagnosticBuilds`、同一性の根拠は `production-equivalence.json`。追加回帰は `campaign-regression/`。

## 入力によるオフライン検証

3版×6装備の18通りで独立移動・射撃・2Pのみの移動・2Pボム・ポーズ・タイトル復帰を確認。各版で再挑戦、タイトルからの再入場、2Pだけの被弾と復帰後の射撃も成功。記録は版別 `offline/`。入力自動化には専用DLLを使うが、この試験群では診断用の状態改変コマンドを使わない。

通常版1.00bのExtraとPractice全6面で、移動・射撃・P2ボム・再挑戦・タイトル復帰を確認。再挑戦はボム1→2、両自機の再初期化ログ増加、ステージ時間の巻き戻りの3条件で検証。記録は `modes/`。

## 面進行の診断

通常版1.00bで通常1〜6面から原作エンディングへ、Extraから原作クリア結果へ到達。会話・ボス・面遷移を原作の処理で進め、両自機の存在と射撃を観測した。

この診断は専用DLLで無敵・最大パワー・ダメージ4倍を使い、時間は原作どおり1フレームずつ進める。最初の試行ではタイマー4倍が原作の厳密な30フレーム目の初期化を飛ばしたため、その診断方式を撤去した。失敗した試行を合格記録へ含めていない。ステージ番号やECL命令位置の飛ばしは行わないが、通常難易度でのクリア、全スペルの自然な発射挙動、ゲームバランスの保証とは扱わない。記録は `campaign/story.json`、`campaign/extra.json`。

## Native同期とTLS

各版で通常DLLを動かす2プロセスへ同じ確定入力を渡し、ボム・再挑戦・タイトル・再入場を含む1,658フレームのdigestが一致。入力停止で双方が待機し、再開後に進行。不正な入力ビットは消費前に拒否。記録は版別 `native-lifecycle.json`。

最終通常DLL・ランチャーのTLS1.3通信では、以下の4組み合わせでステージ進行、両自機の射撃・移動、所有プロセス終了を確認。映像・音声は転送しない。

| ホスト → ゲスト | 時間 | 照合済みフレーム（両側） | 結果 |
|---|---|---|---|
| 通常版1.00a | 60秒 | 3,467 / 3,467 | 成功 |
| 通常版1.00b | 60秒 | 3,455 / 3,455 | 成功 |
| Steam版1.00b | 60秒 | 3,433 / 3,433 | 成功 |
| 通常版1.00b → Steam版1.00b | 60秒 | 3,441 / 3,441 | 成功 |

Steamの切断試験は25秒後にゲストを中止し、ホストが切断を検出して双方終了。終了所要時間は18ms。記録は `steam-1.00b/tls-disconnect.json`。

最終ランチャーの自己テストは11群成功。TLS/pin/256-bit招待鍵、役割・セッション・フレーム順・入力ビット・サイズ境界・期限・通信断・未認証接続・認証後の送信頻度・IPC重複commit・3版識別と相互互換性・旧ルール拒否を確認。記録は `launcher-test-results.txt`。

## 検証の範囲

- 通信は同一PC上の分離プロセスによるループバック。別PC・インターネット・VPN経由の実接続は未実施。
- digestは列挙した状態の不一致検出。全メモリ、ECLの全実行状態、遅延演出の全履歴の同一性を証明するものではない。
- 直接参照の分類と実ゲーム診断を行ったが、全難易度・全スペル・全間接参照を人が通しプレイしたものではない。
- 未知EXE、体験版、他のEXE改変MOD、1.00a/1.00b混在通信は対象外。既知3プロファイル以外は起動を拒否する。
- 公開募集・自動NAT越え・外部中継・途中参加/再接続は含まない。招待制の直接接続を使用する。
